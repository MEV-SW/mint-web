## 화면별 정의

### 1. 소스 관리 — 수집 운영 영역
- **구성**: 운영 카드 4장을 2열 격자로 배치한다(기존 3열 → 2열). 새 카드가 첫 번째다.
  ```
  수집 운영  [전체 소스 수집]     [탐문 파이프라인]
             [커뮤니티 탐문]      [탐문 후보 삭제 기한]
             └ 카드: 아이콘 / 제목 / 설명 한 줄 / 우측 버튼
  ```
  좁은 화면(760px 이하)은 기존대로 1열이다.
- **표시 데이터**: 제목 `전체 소스 수집`, 설명 `공식·중요 게시판 소스 전체 크롤링 · 매일 06:00(KST)`.
- **액션**: `지금 수집` → `POST /api/v1/sources/crawl-all`.
  성공(202) 시 작업 목록을 다시 불러오고 info toast `전체 소스 수집을 백그라운드에서 시작했습니다. 상단 작업 패널에서 진행 상태를 확인하세요.`
  실패 시 서버 `detail`을 err toast로, 없으면 `전체 소스 수집 요청 실패`.
- **상태**:
  - 요청 중·다른 작업 진행 중: 버튼 라벨 `…`, 비활성. 진행 중이면 기존 busy 배너와 버튼 title에 진행 중 작업 라벨.
  - 권한 없음: 카드는 보이되 버튼 비활성, title `총관만 실행할 수 있습니다.`
  - 409(경쟁 상태로 다른 작업이 먼저 시작): err toast로 서버 메시지.
- **권한**: 버튼 실행은 총관(admin)만. 카드는 소스 관리에 들어올 수 있는 사용자 모두에게 보인다.

### 2. 트렌드형 주제 홈 — 메타 줄
- **구성**: 기존 메타 줄의 `집계 주기 1h` 한 칸을 두 칸으로 나눈다.
  ```
  집계 기준 | 트렌드 갱신 1시간 | 자동 수집 매일 06:00 | 최근 갱신 | 소스 | 수집
  ```
- **표시 데이터**: `refresh_interval`이 `1h`면 `1시간`, 그 밖의 값은 그대로 표시한다. `자동 수집 매일 06:00`은 고정 문구다.
- **액션**: 없음.
- **상태**: 로딩·오류는 기존 트렌드 화면 상태를 따른다.
- **권한**: 기존 트렌드 화면과 같다.
