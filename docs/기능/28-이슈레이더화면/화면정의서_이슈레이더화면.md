# 화면정의서_이슈레이더화면

- 기능요청: [W1 화면정의서 (목록·상세·타임라인·1면 밴드·병합분리)](https://github.com/MEV-SW/mint-web/issues/28)
- 소속: [웹 기능묶음 #27](https://github.com/MEV-SW/mint-web/issues/27) / 프로젝트 [mint-release#9](https://github.com/MEV-SW/mint-release/issues/9)
- **디자인 경로**: 디자이너 (§2) — 아래 "경로 판정" 참고
- 작성: 채윤성 / 승인: §3 단독 리포, 승인 상대 없음 (PR 이력만)
- 서버 계약: [B1 API스펙_이슈데이터모델](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md). 이 문서의 표시 데이터·액션은 그 응답 필드를 그대로 쓴다. 필드가 부족하면 양쪽을 같이 고친다.
- 화면 느낌 스케치(배치 참고용, 확정 아님): 구현 담당이 별도 보관. 이 문서가 정보 구조의 기준이다.

## 경로 판정

기존 관리자 CRUD([`AdminAccountsPage`](https://github.com/MEV-SW/mint-web/blob/main/src/pages/AdminAccountsPage.tsx)·[`SourcesPage`](https://github.com/MEV-SW/mint-web/blob/main/src/pages/SourcesPage.tsx))와 목록/상세([`NewsPage`](https://github.com/MEV-SW/mint-web/blob/main/src/pages/NewsPage.tsx)·[`PostDetailPage`](https://github.com/MEV-SW/mint-web/blob/main/src/pages/PostDetailPage.tsx))는 재사용한다.
하지만 **변화 타임라인**, **사실/AI해석/추가확인 배지 체계**, **1면 변화 밴드**는 기존 부품에 없다.
없는 부품이 필요하므로 §2대로 디자이너 경로로 판정한다. 시안 담당은 채윤성.
디자이너가 산출할 것: 아래 화면 5개의 Figma 프레임, 각 화면의 **로딩 / 빈 목록 / 오류 / 권한 없음** 상태 포함(해피패스만 온 시안은 반려). 색·간격·타이포·에셋은 시안이 시각 스펙이므로 이 문서에 적지 않는다.

## 공통 전제

- 전체 기능은 서버 flag `ISSUE_RADAR_ENABLED`에 종속. off면 아래 진입점(내비 항목·1면 밴드·관리자 메뉴)이 나타나지 않고, 기존 1면·뉴스·리포트·개인화·전시모드는 그대로다.
- 로그인 필요. 조직·분야 공개 범위는 서버가 응답에서 이미 걸러 보낸다 — 프론트가 다시 판단하지 않는다.
- 기존 라우팅 구조([`App.tsx`](https://github.com/MEV-SW/mint-web/blob/main/src/App.tsx)): 사용자 화면은 `ProtectedRoute` > `AppLayout` 안, 관리자 화면은 `/admin` + `AdminRoute`/`SuperAdminRoute` 안.
- 상태 데이터는 기존처럼 `@tanstack/react-query`로 가져오고, 실패는 토스트([`useToast`](https://github.com/MEV-SW/mint-web/blob/main/src/components/common/Toast.tsx))로 알린다.

## 화면별 정의

### 1. 이슈 목록

- **구성**:
  ```
  상단  페이지 제목 + 필터 (전체 / 추적 중 / 이번 주 변화) + 분야 선택(사용자가 볼 수 있는 분야가 2개 이상일 때만)
  본문  이슈 목록 — 행 반복
        └ 행: 추적 별표 / 제목 / 한 줄 요약 / 메타(기사 수·출처 수·시작일·마지막 변화) / 상태 배지
  하단  페이지네이션 (기존 목록과 동일 패턴)
  ```
- **표시 데이터**: [`GET /api/v1/issues`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md) 응답 `items[]` — `title`, `summary`, `member_count`, `source_count`, `first_seen_at`, `last_activity_at`, `change_state`, `tracking`, `has_unseen_change`. 날짜는 기존 [`formatDateTime`](https://github.com/MEV-SW/mint-web/blob/main/src/utils/date.ts) 관례.
- **상태 배지**: `change_state` 4값 — `development`(실질 변화) / `correction`(정정 반영) / `duplicates_only`(중복 보도만) / `quiet`(조용함). **네 값은 서로 구분되어 보여야 한다.** `has_unseen_change=true`면 행에 "변화 있음" 표식을 별도로 얹는다(배지와 별개 축).
- **액션**:
  - 별표 토글 → [`PUT /issues/{id}/tracking`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md). 즉시 반영, 실패 시 토스트 + 원복.
  - 행 클릭 → 화면 2로 이동 (`state.from`으로 목록 복귀 경로 전달, 기존 [`PostDetailPage`](https://github.com/MEV-SW/mint-web/blob/main/src/pages/PostDetailPage.tsx) 관례).
  - 필터 칩 클릭 → `filter` query parameter 변경, 목록 재조회.
- **상태**:
  - 로딩: 목록 스켈레톤(기존 [`Skeletons`](https://github.com/MEV-SW/mint-web/blob/main/src/components/common/Skeletons.tsx) 패턴).
  - 빈 목록: `filter=all`이면 "아직 묶인 사건이 없습니다"(크롤·배정이 도는 중일 수 있음 안내). `filter=tracked`면 "추적 중인 사건이 없습니다 — 목록에서 별표로 추적을 켜세요". `filter=changed`면 "마지막 확인 이후 변화가 없습니다". **세 빈 상태는 문구가 다르다.**
  - 오류: 목록 자리에 재시도 버튼 있는 오류 블록.
  - 권한 없음: 해당 없음(로그인 사용자 전체 접근). flag off면 내비 항목 자체가 없음.

### 2. 이슈 상세

- **구성**:
  ```
  상단  뒤로(목록/1면) + 이슈 제목 + 분야 + 추적 별표
  요약  AI 요약 + 신뢰도 표기
  근거  구성 기사 목록 — 행 반복
        └ 행: 출처 / 발행일 / 제목 / 원문 링크 / (커뮤니티면) 미검증 표시
  변화  변화 타임라인 (화면 3)
  하단  액션 (추적 토글, 관리자면 '병합·분리로 이동')
  ```
- **표시 데이터**: [`GET /issues/{id}`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md) — `title`, `summary`, `summary_confidence`, `member_count`, `source_count`, `first_seen_at`, `tracking`, `last_seen_at`, `has_unseen_change`, `members[]`(`title`, `source_name`, `published_at`, `original_url`, `unverified`, `role`).
- **액션**:
  - 화면 진입 시(데이터 로드 후) → [`POST /issues/{id}/seen`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md) 1회 호출. 이 호출은 확인 커서를 갱신하고 추적 의사로 간주된다([B1](https://github.com/MEV-SW/mint-server/issues/29)·[W4](https://github.com/MEV-SW/mint-web/issues/31)와 합의). 타임라인의 "여기까지 확인함" 선·NEW 표식은 **이번 진입 직전의** `last_seen_at`을 기준으로 그린다(진입하자마자 전부 '읽음'으로 접히지 않게).
  - 원문 링크 → 새 탭(기존 관례 `noopener,noreferrer`).
  - 별표 토글 → 화면 1과 동일.
  - (관리자) '병합·분리' → 화면 5로 이 이슈를 선택한 상태로 이동.
- **상태**:
  - 로딩: 상단·요약·근거·타임라인 각각 스켈레톤.
  - 빈: 구성 기사가 1건뿐이면 근거는 그 1건, 타임라인은 `first_report` 노드 하나. "빈 목록"이 아니라 정상.
  - 오류: 404(없음·타 조직·안 보이는 분야) → "이 사건을 찾을 수 없습니다" + 목록으로. 308(병합됨) → 대상 이슈로 자동 이동(사용자에게 "이 사건은 다른 사건으로 합쳐졌습니다" 토스트).
  - 권한 없음: 해당 없음(로그인 사용자 전체). '병합·분리' 진입 버튼은 관리자에게만 보인다.

### 3. 변화 타임라인 (화면 2 내부 영역, 재사용 컴포넌트)

- **구성**:
  ```
  세로 축을 따라 변화 노드가 시간순(오래된 것 → 최근)
  ├ 노드: 날짜 / 배지(들) / 한 줄 / 부연 / (기사 변화면) 출처
  ├ 중복 구간: "중복 보도 N건" 접힘 요약 — 펼치면 개별 기사
  ├ "여기까지 확인함 · {시각}" 마커 (last_seen_at 위치, 커서 없으면 없음)
  └ 마커 아래 노드는 NEW 표식
  ```
- **표시 데이터**: [`GET /issues/{id}/revisions`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md) `items[]` — `kind`, `fact_type`, `headline`, `note`, `post_title`, `source_name`, `duplicate_post_ids`, `actor`, `occurred_at`, `is_unseen`.
- **배지 체계** (구분되어 보여야 함):
  - `fact_type`: `fact`(사실) / `ai_interpretation`(AI 해석) / `needs_check`(추가 확인 필요). `kind`가 `development`·`correction`일 때 노드에 표시.
  - `kind` 자체: `first_report`(첫 보도) / `correction`(정정) / `admin_adjust`(관리자 조정) 은 종류 라벨로.
  - `is_unseen`(NEW): 위 두 축과 **다른 세 번째 축**. 하나의 노드가 "NEW + 사실"일 수 있다.
- **액션**:
  - 중복 구간 "펼치기" → `duplicate_post_ids`의 기사들을 출처·제목·원문 링크로 나열. 접기 가능.
  - 노드의 기사 제목/출처 → 원문 새 탭.
  - `admin_adjust` 노드 → `actor` 이름·시각 표시, 링크 없음.
- **상태**:
  - 로딩: 노드 3개 분량 스켈레톤.
  - 빈: 없음(모든 이슈는 최소 `first_report` 노드 1개).
  - 페이지 초과: `size` 기본 50, 넘으면 "이전 변화 더 보기"로 다음 페이지 이어붙임.
  - 오류: 타임라인 자리에 재시도 블록(상세의 나머지는 유지).

### 4. 1면 변화 밴드

- **구성**:
  ```
  1면(DashboardPage) 최상단, 기존 마스트헤드 아래 / 톱 스토리 위
  ├ 밴드 헤더: "지난 확인 이후 움직인 사건 N" + (선택) 추적 중 총 개수
  └ 카드 반복 — 추적 이슈 중 변화분
     └ 카드: 제목 / 새 변화 요약(배지 몇 개) / 마지막 변화 시각 + 새 기사 수
  변화가 없으면 밴드 영역 자체가 렌더되지 않음 (빈 밴드를 그리지 않는다)
  ```
- **표시 데이터**: [`GET /api/v1/issues/changes`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md) — `items[]`(`title`, `last_activity_at`, `new_revision_count`, `top_change_kinds`, `new_member_count`), `since`. `items`가 비면 밴드 없음.
- **액션**:
  - 카드 클릭 → 화면 2(해당 이슈 상세), 변화 타임라인 영역으로 스크롤 위치 이동.
  - (선택) 밴드 헤더의 "모두 보기" → 화면 1 `filter=changed`.
- **상태**:
  - 로딩: 1면의 다른 영역과 함께 로드되며, 밴드는 자체 스켈레톤 없이 "준비되면 나타남"(기존 [`DashboardPage`](https://github.com/MEV-SW/mint-web/blob/main/src/pages/DashboardPage.tsx)가 영역별 쿼리를 병렬로 다루는 방식과 동일).
  - 빈: 변화 없음 → 밴드 미표시. 1면은 기존과 동일.
  - 오류: `/issues/changes` 실패 → 밴드 미표시(1면 나머지는 정상). 조용히 숨긴다(1면 상단에 오류 블록을 띄우지 않는다).
  - flag off / 추적 이슈 0: 밴드 미표시.

### 5. 관리자 병합·분리

- **구성**:
  ```
  상단  페이지 제목 + 이슈 검색·선택 (제목으로)
  좌측  선택한 이슈 A — 구성 기사 목록
        └ 기사 행: 출처 / 발행일 / 제목 / [분리] 액션
  우측  작업 미리보기
        ├ 분리: "새 이슈로: {기사 제목}" — 확인 시 실행
        └ 병합: 이슈 A + 이슈 B(검색해 선택) → [병합] — 확인 시 실행
  하단  선택 이슈의 수정 이력 (issue_revision 중 kind=admin_adjust 및 전체 흐름)
  ```
- **표시 데이터**: 이슈 검색·선택은 [`GET /issues`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md)(`filter=all`, 제목 검색은 B6에서 query parameter 추가 예정). 구성 기사·이력은 [`GET /issues/{id}`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md) + [`/revisions`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md). 실행은 [B6](https://github.com/MEV-SW/mint-server/issues/33)의 `POST /issues/{id}/merge` · `POST /issues/{id}/split`(그 API스펙에서 확정).
- **액션**:
  - 기사 행 "분리" → 우측에 미리보기(그 기사가 빠진 뒤 이슈 A 상태 재계산 안내 문구). "새 이슈로 분리" 확정 → `split` 호출 → 성공 토스트 + 이력 갱신.
  - 병합: 이슈 B 검색·선택 → "하나로 병합" 확정 → `merge` 호출. 병합 방향(어느 쪽이 남는지) 명시. 성공 시 소스 이슈는 대상으로 리다이렉트된다는 안내.
  - 되돌리기: B6 API가 지원하면 이력 항목에서 "되돌리기". 미지원이면 이 화면에도 없음(§6 — 없는 걸 그리지 않는다).
- **상태**:
  - 로딩: 좌/우/이력 각각 스켈레톤.
  - 빈: 이슈 미선택이면 좌·우 비어 있고 안내 문구. 이슈 A의 기사가 2건 미만이면 "분리" 비활성(분리할 게 없음).
  - 오류: 실행 실패 → 토스트로 서버 메시지 그대로. 화면 상태는 유지.
  - 권한 없음: 비관리자는 `SuperAdminRoute`가 라우트 단에서 막아 화면에 도달하지 못한다. 관리 메뉴에도 항목이 안 보인다.

## 서버 계약 정렬 확인 (B1과 함께 리뷰)

| 화면 요소 | B1 필드 |
|---|---|
| 목록 행 배지 | `items[].change_state` |
| 목록 별표 / "변화 있음" | `items[].tracking` / `items[].has_unseen_change` |
| 상세 요약 신뢰도 | `summary_confidence` |
| 근거 "미검증" | `members[].unverified` |
| 타임라인 "여기까지 확인함" | `last_seen_at` |
| 타임라인 NEW | `revisions[].is_unseen` |
| 타임라인 배지 3종 | `revisions[].fact_type` |
| 중복 접힘 | `revisions[].kind == "duplicates"` + `duplicate_post_ids` |
| 1면 밴드 유무 | `GET /issues/changes` `items` 비었는지 |

부족한 필드가 나오면 [B1 API스펙](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/29-이슈데이터모델/API스펙_이슈데이터모델.md)을 고쳐 맞춘다.
