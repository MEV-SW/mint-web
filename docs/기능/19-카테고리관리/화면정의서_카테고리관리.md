## 화면별 정의
### 1. 카테고리 관리
- **구성**:
  ```
  상단  페이지 제목·설명(PageShell) + "카테고리 추가" 버튼
  본문  카테고리 표 — 이름 / 정렬순서 / 상태(활성·비활성) / 사용 중인 소스 수 / 액션(수정·비활성화)
  모달  추가·수정 공용 폼(이름, 정렬순서) — Modal + Btn 조합, SourceFormFields와 같은 얕은 폼 패턴
  ```
- **표시 데이터**: [`GET /categories`](https://github.com/MEV-SW/mint-server/blob/main/docs/기능/13-카테고리소스스키마/API스펙_카테고리소스스키마.md) 응답의 `id`, `name`, `sort_order`, `is_active`(신규 — 기존 [`NewsCategory` 프론트 타입](https://github.com/MEV-SW/mint-web/blob/main/src/types/personalization.ts)에 없어서 이 카드에서 추가). "사용 중인 소스 수"는 이 화면 전용 파생 데이터로, 기존 [`GET /sources`](https://github.com/MEV-SW/mint-web/blob/main/src/api/sourceApi.ts) 응답을 `category_id`로 집계해 화면에서 계산한다(서버에 새 필드를 만들지 않는다).
- **액션**:
  - "카테고리 추가" → 빈 폼으로 Modal 열기 → 저장 시 `POST /categories`(기존 백엔드 엔드포인트) 호출.
  - 행의 "수정" → 기존 값으로 Modal 열기 → 저장 시 `PATCH /categories/{id}` 호출(이름·정렬순서).
  - 행의 "비활성화" → 확인 후 `DELETE /categories/{id}` 호출. 서버가 409(참조 소스 있음)를 반환하면 `apiErrorDetail`로 그 메시지를 토스트에 그대로 보여준다 — 프론트가 자체적으로 "사용 중" 여부를 먼저 막지 않고 서버 응답을 신뢰한다(기존 [`update_source`/`delete_source` 오류 처리](https://github.com/MEV-SW/mint-web/blob/main/src/pages/SourcesPage.tsx) 패턴과 동일).
  - 이름 중복 저장 시 서버 409를 그대로 토스트로 보여준다.
- **상태**: 최초 로딩은 목록 스켈레톤(기존 다른 관리자 화면과 동일 패턴 재사용). 카테고리 0개면 "아직 만든 카테고리가 없습니다 + 추가 버튼" 빈 상태. 저장·비활성화 중에는 해당 버튼에 로딩 표시(`isPending`), 실패는 토스트로만 알리고 화면은 그대로 유지한다(기존 SourcesPage 관례).
- **권한**: `role==='admin'`만 화면 진입·모든 액션 가능. 비admin은 라우트 단에서 `SuperAdminRoute`가 막아 애초에 화면에 도달하지 못한다(기존 `/admin/accounts`와 동일).
