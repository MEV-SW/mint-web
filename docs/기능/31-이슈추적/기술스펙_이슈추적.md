## 이 카드가 실제로 하는 일

W4의 완료 판정 기준 3개 중 2개는 [W2](https://github.com/MEV-SW/mint-web/issues/29) 구현 때 이미 만들었다:

- "★로 추적을 켜고 끌 수 있다" — `IssuesPage`(목록, 낙관적 업데이트)·`IssueDetailPage`(상세) 둘 다 `PUT /issues/:id/tracking` 이미 연결.
- "상세 이탈 시 커서가 갱신된다" — B1 API스펙은 실제로 "진입 시" 호출로 정의했고(§ "화면 진입 시(데이터 로드 후) → POST /seen") W2가 이미 그렇게 구현했다. 카드 설명의 "이탈 시"는 B1 계약과 다른 표현인데, 이미 구현·테스트된 B1 쪽이 맞는 기준이다.

**이 카드에서 실제로 추가한 것**은 세 번째 기준 "표식이 목록·상세에 뜬다"에서 빠져 있던 **상세 화면 쪽**뿐이다:

## 변경 범위

- `src/pages/IssueDetailPage.tsx`: 제목 옆에 `issue.has_unseen_change`일 때 `NewBadge` 노출(목록에는 이미 있었음, 상세에는 없었음).
- `src/components/common/Badges.tsx`: `ChangeStateBadge` 추가.
- `src/pages/IssuesPage.tsx`: `change_state`/`has_unseen_change` 표시를 스타일 없는 `className="pill"`(이 리포에 `.pill` 기본 CSS 규칙이 없어 실제로는 무늬 없는 텍스트로 렌더되고 있었음)에서 `ChangeStateBadge`/`NewBadge`(기존 `.badge` 시스템, 실제 스타일 있음)로 교체.
- `src/types/issue.ts`: 이제 안 쓰는 `ISSUE_CHANGE_STATE_LABELS` 제거(`ChangeStateBadge`가 대체).
